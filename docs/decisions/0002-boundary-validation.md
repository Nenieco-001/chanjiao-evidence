# ADR 0002 · 校验放在边界，产物用单写者发布

2026-11-09，采用。

这份记录说明本次“去过度防御”的取舍：校验放在哪，产物怎么发布。

决定：每个对外函数入口（`load_panel`、`analyze_panel`、`compare_plans` 等）各校验一次，内部辅助函数直接信任调用方，不重复校验。产物发布采用单写者 + 暂存目录 + 原子改名，拒绝覆盖已有路径，失败时清理本次临时目录；删除并发锁和输入的二次读取比对。

理由：本版要求每个目标输出目录同一时间只有一个写者，由调用方保证；代码不提供并发协调。重复校验增加维护成本，错误信息还经常说不清该怎么改。

影响：以后新增输入格式时，在边界加校验和对应测试，不新增防御性内部断言。校验只放在有真实失败场景和测试的位置。
