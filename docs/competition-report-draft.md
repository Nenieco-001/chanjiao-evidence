## 一、现状差距分析

**目标与数据口径**

- 目标专业：计算机科学与技术。目标学校、方案版本及适用入学届别：**待补**。
- 城市：北京、上海。行业：计算机、通信和其他电子设备制造业；软件和信息技术服务业。
  行业取独立的“上市公司行业”列，只说明上市公司标签，不能认定每个用人单位或岗位的实际行业。
- 数据总体：上市公司招聘年度 CSV 的目标切片，标为 `historical`。
  不混入应届生库；没有专业字段，岗位名称规则只是目标专业的岗位族代理，包含有经验岗位。
- 画像窗口：2016、2023 全年及 2026-01-01—03-10；回测另用 2024、2025 全年。
  平台匿名、采集范围变化，不能把年度记录数相连解释成市场需求升降。
- 按列名解析 CSV、分年解释同名字段；在年度目标切片内按企业、岗位、城市、发布日期和薪资近似去重。
  不按招聘人数加权，不把发布记录数当有效岗位人数。细则沿用工作台，不在此改规则。
- 技能只统计固定词表的文本提及，未确认“必备要求”，也没有真实人工标签精确率。
  薪资是报价区间中点的中位数，单位按月薪字段解释为元/月，正式字典仍缺；不是毕业生起薪。
- 百分比注明分母；误差用比例原值，`0.01 = 1 个百分点`。
  下列占比均以本年度去重目标样本为分母，薪资中位数只用有效区间。

  JavaScript 2,578（20.33%）。有效薪资区间 9,714（76.62%），中点中位数 **12,500 元/月**。
- **2023**：筛中 4,889 条，剔除 854 条，保留 **4,035** 条；北京 2,752、上海 1,283。
  软件行业 3,451（85.53%）、电子设备制造业 584（14.47%）；软件开发 1,951（48.35%）、
  数据分析与工程 703（17.42%）、系统运维与安全 687（17.03%）。
  Python 提及 2,905（72.00%）、Linux 1,637（40.57%）、Java 1,355（33.58%）。

  C++ 62（21.68%）。有效薪资区间 284（99.30%），中点中位数 **17,250 元/月**。

配图使用各年独立技能条形图，统一比例尺，标年份、窗口、分母和“词面提及”。
不画跨年招聘总量趋势线，不把词频换算成学时配额。

**回顾性回测：保留全年对照和收缩后的共同支持结果**

2024 去重目标样本 **3,272** 条，2025 为 **3,560** 条。
2024 使用已具备的 2016/2023 作为训练年度，2025 使用 2016/2023/2024；没有补齐缺失年份。
固定比较“保持最近年度”和“年度等权均值”，后者薪资预测是年度中位数的均值。
MAE 是平均绝对误差，TVD 是总变差距离；岗位族覆盖固定五类，技能覆盖全部 12 词，Top-5 固定除以 5。
以下依次列岗位族 MAE / TVD、技能 MAE / Top-5、薪资绝对误差，均为两市合计。

- 全年 **2024 最近年度**：0.047668 / 0.119170；0.074032 / 5/5；**500 元/月**。
- 全年 **2024 年度均值**：0.018726 / 0.046815；0.033291 / 4/5；**1,750 元/月**。
  份额误差较小，但 Top-5 和薪资误差更差。
- 全年 **2025 最近年度**：0.008474 / 0.021185；0.013013 / 5/5；**0 元/月**。
- 全年 **2025 年度均值**：0.020242 / 0.050606；0.018769 / 5/5；**1,166.67 元/月**。
  三项误差均未优于最近年度基线；薪资中位数相同也不表示逐岗位预测准确。

共同支持指：各训练年与目标年在平台标签、月份、城市、行业、学历、经验上逐层取共同值，
再要求六维完整组合在每年都出现。平台同号视为可比是**未确认假设**，切片内权重没有平衡。

- **2024**：最终训练/目标样本按 2016/2023/2024 排列为 **543 / 89 / 597**，
  目标覆盖 **597/3,272（18.25%）**；共同完整组合 29 个。
- **2025**：按 2016/2023/2024/2025 排列为 **358 / 42 / 486 / 39**，
  目标覆盖仅 **39/3,560（1.10%）**；共同完整组合 13 个。
- 月份层共同值为 5、6、7、8、9、10、12 月，完整组合还会继续删样，不能称全年或年初同期。

相同指标在共同支持切片上的结果：

- **2024 最近年度**：0.037762 / 0.094405；0.033957 / 4/5；**2,000 元/月**。
- **2024 年度均值**：0.010827 / 0.027067；0.048476 / 4/5；**499.75 元/月**。
  岗位族和薪资误差较小，技能 MAE 更差，Top-5 相同。
- **2025 最近年度**：0.032352 / 0.080880；0.047206 / 4/5；**500 元/月**。
- **2025 年度均值**：0.036836 / 0.092091；0.048668 / 4/5；**1,083.17 元/月**。
  没有严格优于最近年度基线的指标。收缩改变了比较对象，不能把分数变化称作算法改进。

低覆盖与失败组随主结果展示：2024 平台13仅 1 条，2025 电子设备制造业仅 2 条；
两折分别有 90/101、108/117 个匹配后空组，不能删去空组或用零误差填补。
匹配切片的企业同名目标记录重叠为 492/597（82.41%）、37/39（94.87%），
疑似重复岗位为 43/597（7.20%）、8/39（20.51%）。这些是目标记录数，
不是独立企业数或确认转发数；没有跨年企业隔离，误差可能受重叠影响。
规则已看过 2026，支持选择又使用目标年协变量，因此只能称回顾性描述，不能称独立留出预测。

**供给侧占位与三维差距**

真实培养方案、课程大纲、学分、学时、目标达成、学生结果、方向容量及招生数据均**尚未取得**。
当前只保留以下待核验清单，不能写成真实缺课量或人才缺口：

- 技能结构：已有需求词面；待补课程目标、考核证据和教师复核，才能讨论内容承接。
- 培养方向：已有岗位族结构；待补现行方向、学生意愿、先修和师资，才能讨论分流容量。
- 规模匹配：已有发布记录样本；待补有效招聘人数与代表性校准、毕业供给、流动和就业反馈，
  才能讨论招生建议。记录数减少或增加都不自动触发缩招或扩招。

接口使用现有 [curriculum schema](../analysis/competition/curriculum.schema.json) 与
[课程占位 JSON](../analysis/competition/curriculum-placeholder.json)。下面原样展示现有样例；
**16 学时仅为人工构造的接口数值，不是任何真实学校的课程或调整建议**。

```json
{
  "schema_version": 1,
  "evidence_mode": "synthetic",
  "label": "示例占位",
  "school": null,
  "major": "计算机科学与技术",
  "source": null,
  "courses": [
    {
      "course_id": "demo-python",
      "title": "示例占位：程序设计模块",
      "hours": 16,
      "credits": null,
      "semester": null,
      "prerequisites": [],
      "skill_mentions": ["Python"],
      "evidence_location": "人工构造的接口样例，无真实学校来源"
    }
  ]
}
```

该 schema 固定 `synthetic`、学校/来源为 null，仅服务示例。
接入真实学校要另行升级契约并登记来源、版本、许可和原文位置，不能直接改个标识充当历史证据。
`curriculum_gap` 只做词面集合覆盖，需求为 historical、课程为 synthetic；
不把比例减去学时，不从“未覆盖”推断学生不会，也不因招聘少提就删除基础目标。

**本节续填清单**

- **证据**：上述数值摘自已验收分析报告；画像、全年和共同支持结果分别注明对象和分母。
- **假设**：岗位族可作为选定专业的需求线索；匿名平台同号可能可比；月薪单位按字段解释，均待核实。
- **待补**：供给负责人登记学校与方案版本；数据负责人申请正式字典、平台说明与许可；
  独立复核者标注技能提及和必备要求。材料齐全前，三维差距保持“待核验”。

## 二、方案设计

**设计目标：把需求线索变成可审议的动作单，目前没有已选出的真实学校调整方案。**
保留现行方案作为共同对照。先取得供给材料，再由专业教师确认目标和约束，最后填写候选动作。
调整理由不能只有热门词频；每项都要说明被替代内容的损失及如何承接。

**课程增减、合并与学时调整模板**

每个候选复制下列动作单，未取值的字段保持“待补”：

- 动作编号 / 目标学校及入学届别 / 课程原名与原文位置：待补。
- 动作类型：新增、减少、替换、合并或保持；具体内容边界：待补。
- 调整前 → 后学时、理论/实践拆分、学分及换算规则、开课学期：待补。
- 目标承接：原学习目标、候选目标、删减后承接课程与独立考核：待补。
- **证据栏**：关联本稿第一节的需求分组及真实大纲位置、教师核验记录；目前大纲证据缺失。
- **假设栏**：新增教学机会如何影响内容覆盖、学生能力与负荷；参数来源和区间：待补。
  未知增益要保留零与负值可能，不能按需求占比直接定学时。
- 资源核算：先修、总学时/学分、毕业要求、学期负荷、师资、实验容量、成本和准备周期：待补。
- **待决策栏**：教师是否认可目标承接、学院可调范围、责任人与审批时间：待补；
  未经核定标为“候选”，不能标“推荐实施”。

**培养方向与分流模板**

- 方向名称与现行课程组合：待补，不把岗位族名称直接写成学校已有方向。
- **证据栏**：需求岗位族结构、学校现行方向及资源表、学生意愿调查和先修达成证据；后面三项待补。
- **假设栏**：方向需求情景、参与意愿和课程通过情况；来源与范围待补。
- 分流规则：申请时点、先修门槛、容量核算、超额候补、补修、转向与退出机制：待决策。
  容量按方向修读人数与教学组织核算，不能按招聘占比直接分配人数。
- **待决策栏**：学院确认容量，教师确认先修，学生代表复核机会分配与额外负荷；均待补。

**基于就业反馈的招生调整模板**

- **证据栏**：届别招生、毕业/延毕/升学、就业分母与固定随访窗、去向城市行业、
  有效岗位人数及覆盖校准：均待补。招聘报价不能替代毕业生起薪。
- **假设栏**：培养时滞、地区流动、行业吸纳和需求代表性；参数与依据待补。
- 决策流程：核对已知届别反馈 → 检查来源与供需口径 → 人工审议是否调整 →
  检查多届在校生资源负担 → 形成下一届建议。缺输入时记录“无法判断”。
- **待决策栏**：触发阈值、平滑窗口、幅度上限、冷却期、审批权限与复核时间均待定；
  暂不提供扩缩招比例，不承诺反馈收敛。

**本节续填清单**

- **证据**：第一节提供需求线索；课程、方向、招生三项模板覆盖赛题方案必备项。
- **假设**：动作到学习与就业的机制仍需独立材料支持，当前模板未运行优化或选出方案。
- **待补**：供给负责人填写动作与约束原件；教师确认基础能力底线；学院核定容量、成本和招生权限。
  交付时保留否决的动作及原因，不只留下可行候选。

## 三、效果验证

**当前可报告需求样本的回测误差；尚无真实课程改革、学生能力或就业效果。**
赛题要求四年就业率、起薪和技能匹配度对照，本稿把这三项列为**待补、当前不可估计**。
不从招聘词频、薪资报价或合成 CLI 效应推导四年收益，也不填精确数字回应格式要求。

**把四类证据分别交付**

- **任务输出正确**：已有脚本测试、产物哈希与确定性记录，来源见任务板。
  支持既定规则的实现正确，不能支持抽取准确或学校改革有效。
- **需求样本预测误差**：已有第一节的两种方法和两折回顾性对照；
  无优势、小样本、空组和企业重叠一并保留，不承诺未来市场预测准确。
- **情景内部一致**：待学校动作、资源、教学参数及其依据齐全后执行；目前没有方案推演结果。
- **真实培养效果**：缺历史改革、学生结果和可比对照，当前无法识别；
  团队现阶段不能开展真实教学试点，后续优先争取已有历史记录或独立考核，不能以试点设计冒充结果。

**待执行的同条件验证框架**

- 先登记研究对象、动作、原方案对照、届别、城市行业、结果单位和固定随访窗。
  课程内容覆盖、共同能力考核、岗位适配、学业负荷、就业率与起薪分别定义分母和测量方式。
  当前学校、届别、结果窗和能力评分标准均待补。
- 在相同动作空间、硬约束和预算下比较现行方案、热门技能贪心、名义情景候选和稳健候选。
  这些是后续方案比较设计，区别于已运行的两种需求回测方法；本批没有实现这些候选或新增实验。
- 开发阶段完成候选和参数选择后冻结，再由独立人员保管评价数据。
  不把看过的 2026 当留出；企业和转发隔离、人工标签、未见月份或届别仍待取得。
- 前后对比：当前基线、同一届维持原方案的期末结果、调整方案的期末结果三者分开，
  以相同生源和外部需求轨迹比较，避免把时间变化归给课程。
- 反事实对比：仅在相同初始条件、需求与资源假设下比较两方案差值。
  仿真的“如果换方案”属于条件推演；历史改革数据另须审查选择机制、共同支持、同期政策和对照趋势。
  当前需求切片共同支持不能替代学校改革识别。
- 情景推演：乐观 / 基准 / 悲观分别登记需求结构、教学增益、毕业与分流、师资容量和成本。
  每个参数写来源、范围、负责人和冻结版本；当前全部待补，不虚构概率或收益。
  固定方案后做单因素与联合压力检查，分别报告能力/内容指标、负荷、成本、最差值与相对原方案差值。
  只检查有限情景时，最差值只覆盖该集合；情景范围不是统计置信区间，改善情景占比不是现实改善概率。
- 真实结果可得时：先检验结果模型是否优于最近届别等简单基线，再讨论动作覆盖和外推。
  若课程组合从未出现、结果口径不一或对照不可比，就停止改革效果估计，保留条件分析。
  零、负、无优势与无法识别都属于正式结果。

**失败与建议反转登记**

- 匿名平台无法确认同源，或某层/完整组合没有共同支持：停止该可比评分，保留 null 和断层原因。
  已发生的低覆盖限制见第一节；不能用全年分数补齐空组。
- 人工复核发现否定、模板或岗位代理误判影响结论：撤回相应缺口排序，修规则后另封存评价集。
- 候选违反先修、毕业要求、基础能力底线或师资容量：判为不可行，返回原方案或较小改动候选。
- 新模块增益不足以抵消删减目标、额外负荷和成本，或零/负增益条件下优势消失：
  记录盈亏平衡条件及其证据范围，保留原方案。当前没有估计出的反转阈值。
- 独立评价不优于原方案/简单候选，或合理权重与机制变化就改变推荐：
  报告无优势或推荐反转，交教师决策，不挑选有利情景。
- 就业分母、随访窗、生源或同期政策不一致，招生反馈出现过度扩缩或容量冲突：
  停止收益解释或调整建议，补齐口径与历史约束后再评。

**本节续填清单**

- **证据**：已有需求回测及其失败项；四年就业率、毕业生起薪、学生技能匹配效果均无可估计结果。
- **假设**：后续条件推演依赖教学机制、外部需求和资源范围；迁移与敏感性参数不是估计结果。
- **待补**：验证负责人登记指标、可用历史记录、独立评价划分、参数来源及反转条件；
  未取得供给和结果数据前，此节是验证协议骨架，不写“方案已有效”。

## 四、风险评估与应对

**风险按触发信号、影响、动作和责任角色记录，具体人员与阈值由组员续填。**

- **师资与实验容量不足**。触发：教师确认无法承担候选内容，或方向修读人数超过可用容量。
  影响：无法开课、分流受阻、成本超支。应对：先核定资源日历与目标承接，再分阶段调整；
  无法满足就缩小动作或保持原方案。责任：专业负责人、教务；姓名与核定日期待补。
- **学生适应与先修负担**。触发：先修基础不足、课表冲突、共同考核或负荷反馈低于约定底线。
  影响：延毕风险、方向机会不均、关键基础能力退化。应对：补修与转向机制、负荷上限、
  保留基础目标；先收集历史达成与意愿再定分流。责任：课程组、学生事务；底线待教师确认。
- **数据许可不明**。触发：来源授权、再分发或公开演示范围未获确认。
  影响：聚合、图表或原文不能按预期公开。应对：登记来源、版本、许可与合规结论；
  确认前不公开受限材料，演示使用明确标识的合成接口；原始记录与证据定位留本机。
  责任：数据负责人、协调者；许可答复与可公开清单待补。
- **平台覆盖、季节及模板偏差**。触发：来源组成变化、同号身份不明、共同支持低覆盖或技能模板集中。
  影响：伪趋势、缺口排序错误和外推失效。应对：逐年/分组列分母、保留全年对照与空组，
  核实平台字典并做独立标注；无法形成支持就停止该比较。责任：需求分析与复核者。
- **把代理改善误当真实效果**。触发：用词面覆盖、报价或同源仿真分替代能力、起薪或就业率。
  影响：方案理由与评审结论超出证据。应对：按第三节分层交付，冻结后评价；
  缺结果就保留待补，保留零/负/无优势条件。责任：验证负责人、答辩主讲。

**评审五维度与材料索引**

- **差距分析准确性**：第一节的样本分母、分年画像、共同支持和三维待核验清单；
  完成需求侧描述，真实供给差距仍缺材料。
- **方案可操作性**：第二节三类模板、目标承接、资源与审批字段；当前是待填动作单。
- **验证说服力**：第一节回顾性结果及失败项、第三节同条件对照与反转协议；没有真实改革效果。
- **风险评估与应对**：本节风险的触发、动作、责任角色；具体人员与资源承诺待补。
- **材料规范与现场表现**：报告数字追到分析报告和本机产物版本；PPT、视频沿用同一套数字与边界。
  后续报告 PDF、可运行数据支撑、视频和实际 PPT 另行制作、复核许可与格式，本批仅交 Markdown 骨架。

**本节续填清单**

- **证据**：平台覆盖、支持收缩、抽取误判和供给缺失已有记录；师资/学生风险尚无本校观测结果。
- **假设**：上述触发与处置是风险管理设计，不是已发生的学校事件，也没有估计发生概率。
- **待补**：协调者分配实名责任人；学院确认资源和学生支持安排；数据负责人核实公开许可；
  交付负责人完成 PDF、PPT、视频与可复核附件，冻结同一版本后再送审。
