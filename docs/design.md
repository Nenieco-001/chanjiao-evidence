# 首版设计

2026-11-09

## 要回答的问题

在没有线下试点的情况下，如何用过去相近专业的培养改革，估计某项培养措施对明确学生结果的影响，再说明该证据支持当前方案的条件和边界。

首个切片选择“新增企业实习是否改善毕业后固定时间窗内的就业率”。就业率、收入、岗位对口和任务能力分别分析。学校整体就业率不能替代学生能力测量。

## 首版闭环

输入采用学校或专业层面的平衡面板。每个单位有固定的处理组身份、共同改革时点，首版固定为两个改革前年份及改革实施年份。每次仅分析一个改革和一个比例指标。数据契约明确单位、时间窗、改革暴露、来源及合成标识。

先校验数据，再分别计算处理组前后变化、同期对照变化和双重差分。对单位变化量回归 `delta ~ treated`，调用 statsmodels OLS，用 HC3 与 t 分布给出近似区间。每个单位只有一条变化量，单位等权。前一段改革前年份作为伪改革检验。进一步删除单个单位检查稳定性，并报告需要多大的未观测差异趋势才能抵消估计优势。

输出 JSON 报告、输入和源码哈希、依赖版本、研究限制。所有结果按 synthetic 或 historical 标识。历史数据的估计仍依赖平行趋势、无提前反应、无干扰和口径稳定等假设。

方案比较输入完整的学分配置、资源成本和与该项改革对应的方案。首版仅支持“保持原方案”与“一项已有证据对应的改革”比较，在总学分、基础课程最低学分、实习容量和预算约束下筛选。作用范围折扣和偏差预算由用户明确设定，作为敏感性假设记录。保持原方案始终参与排序。首版不估计多个措施的交互作用。

## 代码边界

- `dataset.py` 负责元数据与面板校验。
- `estimation.py` 负责 DiD、伪改革、删除单位诊断。
- `planning.py` 负责约束与单项改革方案比较。
- `pipeline.py` 连接输入、估计、方案比较与可复现报告。
- `cli.py` 提供离线命令行入口，拒绝覆盖已有产物目录。
- `data/examples/` 只放可公开的合成数据与生成脚本。
- `data/evidence/` 放公开论文的结构化摘要与原始链接。

## 开源参考

statsmodels 作为实际统计依赖。Cookiecutter Data Science 提供数据、源码、文档和产物分离思路。DoWhy 的建模、识别、估计、反驳流程用于设计研究规范。pyBKT 和 DoubleML 作为后续模型候选，接入须有独立需求和验证。各项目版本、许可证和借鉴范围见 `docs/open-source.md`。

## 验收

命令行在干净安装后跑通。手算用例验证四格 DiD，零效应用例回到零，负效应保留负号。重复记录、口径缺失、非有限数、非平衡面板和处理组变更均被拒绝。约束不合格方案有明确原因。相同输入重复运行的结果与内容哈希一致。CI 在 Windows、Linux 和 Python 3.11、3.13 上执行安装、测试、格式检查、打包和命令行。
