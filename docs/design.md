# 首版设计

2026-11-09

这份文档说明首版解决什么问题、怎么做、边界在哪，以及做到什么算完成。

## 要回答的问题

没有线下试点时，用过去相近专业的改革反推某项培养措施对学生结果的影响，并说明结论成立的条件。

首个版本只回答一件事：新增企业实习，是否改善毕业后固定时间窗内的就业率。就业率、收入、岗位对口和任务能力分开分析。学校层面的就业率不能替代学生能力测量：前者反映毕业生就业情况的变化，后者要看学生个体数据。

## 首版流程

输入是学校或专业层面的平衡面板。每个单位固定属于处理组或对照组，改革年份相同，只包含改革前两个年份和改革当年。一次运行只分析一项改革和一个比例指标。

处理步骤：

1. 先校验外部输入（CSV、JSON、命令行参数）。
2. 分别计算处理组和对照组的前后变化，再相减得到 DiD（双重差分）估计。等价做法是对单位变化量回归 `delta ~ treated`，调用 statsmodels 的 OLS，用 HC3 协方差和 t 分布给出近似区间。
3. 每个单位只有一条变化量，单位等权。
4. 用改革前两年做伪改革检验：如果改革前已经出现类似差异，平行趋势假设就不可信。
5. 逐单位删除，检查单个单位对结论的影响。
6. 报告“需要多大的未观测差异趋势才能抵消估计优势”，让读者知道结论有多稳。

输出 JSON 报告、输入和源码哈希、依赖版本、研究限制。所有结果标明 `synthetic` 或 `historical`。

## 识别假设与边界

历史数据的估计只在以下条件成立时解释为 ATT（处理组平均处理效应）：

- 处理组和对照组的未处理趋势相同（平行趋势）。
- 没有提前反应和干扰。
- 结果口径与人群构成稳定。
- 单位相互独立，改革时点相同，单位等权。

伪改革接近零只说明这段数据没有显示明显差异，不能证明平行趋势。样本少、历史期短时检验能力有限，HC3 区间也是近似值。存在同期改革包时，效应属于整个实际改革，不能拆给单项措施。

这些边界决定结论能说到哪一步：估计的是这批学校在这个时间窗内的变化，换学校、换年份要重新估计。

## 方案比较

输入完整的学分配置、资源成本和“一项已有证据对应的改革”。首版只比较“保持原方案”和“一项改革”，在总学分、基础课最低学分、实习容量和预算约束下筛选可行方案。

迁移系数（表示假设历史效应有多少能用于目标学校）和偏差预算由用户明确设定，作为敏感性假设记录，不当作估计结果。保持原方案的增量恒为 0，始终参与排序。只有一项改革的保守增量大于 0 才会被选中；相同收益优先低成本。首版不估计多项措施的交互作用。

## 环境与依赖

Python 3.11–3.13，statsmodels 0.15.0，默认离线运行。示例只用合成数据，公开仓库保留数据来源与许可边界。运行版本以 `pyproject.toml` 和环境文件为准。

## 接口

| 函数 | 职责 |
| --- | --- |
| `load_panel(csv_path, metadata_path)` | 读取并校验面板和元数据，返回 DataFrame 与元数据。 |
| `parse_panel(csv_bytes, metadata_bytes)` | 解析并校验同一份输入字节；pipeline 用它保证报告与清单同源。 |
| `analyze_panel(frame, adoption_year)` | 返回主估计、改革前伪改革和逐单位删除诊断。 |
| `compare_plans(config, effect)` | 返回每个方案的可行性、资源约束和敏感性排序。 |
| `run(panel_path, metadata_path, plans_path, output_dir)` | 校验全部输入后发布一个全新产物目录。 |

效应是比例差值，0.01 对应 1 个百分点。区间和方案优势只说明当前设计和样本，不能直接解释为真实学校效果；真实数据接入前，这些数字只验证实现。

## 验收

首版以这些结果算完成：

- 干净安装后命令行能跑通。
- 手算用例验证四格 DiD；零效应用例回到零；负效应保留负号。
- 重复记录、口径缺失、非有限数、非平衡面板、处理组变更都被拒绝，并说明该怎么改。
- 约束不合格的方案有明确原因。
- 相同输入重复运行，报告和清单内容哈希一致。
- CI 在 Windows、Linux 和 Python 3.11、3.13 上执行安装、测试、静态检查、打包和命令行。

本地验收命令见 [贡献指南](../CONTRIBUTING.md) 的“验收与提交”。
