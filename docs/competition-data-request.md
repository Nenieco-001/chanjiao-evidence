# 产教智对：供给侧数据申请与验收单

**以下全部是待申请材料，不代表已经取得。** 请学校/赛方按七组、21 个字段包交付，
先覆盖一个经校方确认的目标专业，再讨论其他学校和专业。
用途边界以[报告第一至三节](competition-report-draft.md#task-1)和
[现有三维差距清单](competition-analysis.md#供给接口与三维差距清单)为准；
申请落实情况回填[提交检查表](competition-final-checklist.md)，不另造学校数字。

## 一、接收方式与共同要求

- 学校联系人由教务牵头，分别转课程组、教学质量、招就、学生事务、资源和数据管理部门；
  赛方联系人负责正式样例、就业汇总、字段字典、评测集及数据授权答复。
  团队由供给负责人登记、验证负责人验收、协调者确认可公开范围，具体姓名待协调者填写。
- 每个字段包回传：有/无/受限、可交时间、联系人角色、文件版本、来源、适用届别、
  字段字典、缺失说明及许可范围。没有就明确记“未提供”，不要以 0、示例值或推算值补齐。
- 优先收正式文件 PDF 与结构化 CSV/XLSX 导出；保留文件页码、表号、行号等定位，
  提交方附原件与导出表的对应说明。单位、分母、统计日期、更新与修订规则一并交付。
- 本文的“最小可用样本”是启动该用途的最低材料覆盖，**不是统计功效或代表性保证**。
  三维差距先核对同一专业、方案版本与适用届别；历史比较须另审查选择、同期政策和对照。
- 受限材料由学校通过批准渠道提供并在授权地点保存，不进 Git；当前赛题合规要求见
  [赛题说明 1.4 与 5.1](competition-brief.md#五数据口径与协作约定)。
  若涉及非公开校内材料，先请赛方书面确认参赛是否允许及展示条件，确认前不纳入参赛附件。

## 二、七组申请单

### G1｜培养方案

**字段（3 包）**

- D01 方案身份：学校授权代号、专业代码/名称、版本号、适用入学届别、审批/实施日期、文件来源与原文定位。
- D02 培养目标：毕业要求、能力目标编号、目标定义、必修/选修模块、现行培养方向及修读规则。
- D03 改革轨迹：前后版本差异、措施内容、覆盖届别/单位、实际执行起点、同期改革、修订理由及执行证明。

**用途**：确定比较的现行方案和估计对象，区分改了什么与何时执行；支持技能/方向差距核验。

**最小可用样本**：一个目标专业的一份完整有效现行方案，覆盖全部毕业要求和课程模块。
讨论历史改革再补至少一组前后版本和实际执行记录；只有现行方案时不研究改革效果。

**责任角色**：校方专业负责人/教务确认版本与执行；团队供给负责人登记，验证者抽查原件。

**验收标准**：版本、届别与日期齐全；课程目录能回查批准文本；目标编号和模块口径一致；
“计划实施”和“已经执行”分列，不能用审批日期代替执行日期。

**缺失替代**：使用经核验的公开正式方案做该公开专业的内容核验，注明年份与许可，不能替代目标校；
完全没有则只交需求线索与空白动作单，不填写真实学校缺课量。

### G2｜课程大纲

**字段（3 包）**

- D04 课程身份：稳定课程代码、名称、必选修属性、关联方案版本、所属模块、开课学期、大纲版本与原文位置。
- D05 教学内容：学习目标编号、章节/任务、理论与实践内容、覆盖范围、目标到毕业要求的映射。
- D06 考核承接：考核任务与评分量规、各目标考核权重、实践产物要求、删减目标由哪门课程/哪项独立考核承接。

**用途**：把岗位词面线索转成教师可审核的内容与考核关系，避免把课程名命中当学生能力。

**最小可用样本**：每个拟调整课程及其先修、替代、承接课程的完整现行大纲；
若要宣称整个专业缺某能力，须覆盖该方案全部相关必修及实际可选修路径，不能只查一门课。

**责任角色**：课程组/专业教师提供并签认目标映射；团队供给负责人整理，独立复核者核对定位。

**验收标准**：D04 与 D01 版本对应；每项内容和目标可追到大纲与考核依据；
教师确认覆盖的深度与适用修读路径；未取得或未覆盖明确分开，不把缺文件当缺教学。

**缺失替代**：课程目录仅用于标记待核验；公开大纲或教师访谈须单独登记来源和性质，
没有正式考核材料时只讨论内容线索，不判能力达成、不生成确定性删课建议。

### G3｜学分学时与先修

**字段（3 包）**

- D07 计量规则：课程学分、总学时、理论/实验/实践拆分、单位、学校换算规则及实习学分认定办法。
- D08 修读约束：先修代码、先修类型、并修/互斥/替代规则、开课频次、学期、方向准入和毕业底线。
- D09 调整核算：现行与候选前后学分学时、总量与模块上下限、各学期负荷、被替代内容、目标承接和审核记录。

**用途**：检查总量守恒、基础目标、先修链和课表负荷，区分可行候选与未获批准的想法。

**最小可用样本**：同一方案下全程课程学分/学时台账及完整先修关系、现行毕业规则；
每项候选另交前后核算单。缺全程台账只能审查局部，不声称整体满足毕业条件。

**责任角色**：教务确认规则、排课人员核查学期冲突，课程组确认承接；团队供给负责人汇总。

**验收标准**：各拆分和总量按校规核平，学分与学时分别核算；先修均能定位到课程，
不存在未解释的循环或断链；候选变动有承接与审批，不能按招聘占比分配学时。

**缺失替代**：动作单数值保持待补，只写核算流程；禁止套用其他学校的换算比。
现有[synthetic 占位](../analysis/competition/curriculum-placeholder.json)只验接口，不拿其中 16 学时填校方表。

### G4｜学生能力与评教

**字段（3 包）**

- D10 能力测量：专业/届别/方向分组、考核时间、共同任务/量规版本、参加与应参加人数、目标达成人数及缺测原因。
- D11 学习过程：先修达成、通过/重修/延毕相关人数、修读路径分布、教学负荷与支持需求的去标识汇总。
- D12 意愿与反馈：方向选择意愿、评教维度、负荷/适应反馈、问卷时间、邀请/回应人数、响应率及汇总方法。

**用途**：区分课程内容覆盖与学生能力，核定分流可达性、补修和负荷风险；评教不能代替能力考核。

**最小可用样本**：一个完整修读群体的一轮共同考核与一轮反馈，附各自总体和响应分母；
做前后或方向比较时，需同口径至少两个时点/群体及生源、选课差异说明，不能只交高分样例。

**责任角色**：教学质量部门/课程组持有原始记录，学生事务提供意愿汇总；团队验证负责人验收测量口径。

**验收标准**：不含个人标识；各分组分母、缺测、量规变更可追溯；小组抑制后不能由总计反推出个人；
非响应和自选群体单列，主观满意度与共同能力测验分开。

**缺失替代**：教师仅核验内容目标，学生能力、适应率和分流意愿记未知；
若组织新调查须先取得学校和赛方许可，仅收汇总，不以少数访谈给出总体达成率。

### G5｜就业与升学

**字段（3 包）**

- D13 届别流量：专业/方向/毕业届别、招生数、在校与毕业/延毕人数、就业/升学/待就业/失联类别人数及分母规则。
- D14 结果指标：就业率、起薪、行业/岗位/地区、专业对口与技能匹配定义、固定随访窗、调查日期、有效样本及薪资统计规则。
- D15 比较条件：历史改革执行与覆盖分组、处理/对照单位代号、改革前后结果、生源汇总、同期政策、缺失/修订与追访方式。

**用途**：建立真实毕业供给和就业基线，审查招生反馈；只有比较条件足够才讨论培养效果与四年外推。

**最小可用样本**：优先申请目标专业近 3–5 届完整同口径汇总，含招生到毕业及固定毕业后时间窗的结果。
若走现有三年 DiD（双重差分）入口，至少需改革前两年与改革当年、处理/对照各 3 个单位的平衡面板；
这只是[当前契约](data-contract.md#面板-csv)门槛，不保证平行趋势、统计功效或可外推四年。
多期/分期改革保留完整记录，另设计方法，不为适配入口删年份。

**责任角色**：招就部门/校友调查部门确认分母与随访，教务确认改革，赛方提供承诺的就业汇总及字典；团队验证负责人审查。

**验收标准**：类别互斥/交叉规则清楚，人数与分母核平；升学和失联不混入就业；
起薪注明税前/税后、月/年、薪数、有效样本和币种，拒答不补零；改革与对照保持相同结果窗。
历史来源与许可可追溯，汇总可查原件；不同口径不能硬拼成趋势或直接送估计入口。

**缺失替代**：公开就业质量报告只作其覆盖人群的背景，招聘报价保持“报价”；
没有校级结果就不估本校就业率、起薪收益或招生比例。具备参数依据后可单列条件情景，不能称真实效果。

### G6｜师资、容量与预算

**字段（3 包）**

- D16 师资：可承担模块、任课资质/能力范围、可用学期工时、培训/备课周期、替代教师安排（按角色汇总，无需姓名履历）。
- D17 容量：班级/方向上限、实验室与设备席位、时间占用、实习名额及合作期限、课表冲突、候补/退出/转向安排。
- D18 预算：现行成本、增量一次性与经常性成本、币种/价格时点、预算上限、采购与准备周期、审批责任及资源承诺期限。

**用途**：审核候选能否开课与落地、是否挤占基础能力或其他年级资源，并设计风险触发后的缩小动作。

**最小可用样本**：目标专业现行一个完整教学周期的资源表，加每个候选的增量核算；
招生或四年情景另需覆盖多届在校生的四年资源计划及每年承诺，不用一年容量代表四年。

**责任角色**：学院/专业负责人、教务、实验中心、实习管理与财务分别确认；团队供给负责人交叉核算。

**验收标准**：容量标时段与占用，避免同一师资/席位重复分配；成本分项能追溯，
硬约束、意向和已批准承诺分列；冲突有处置人与时点，不把尚未获批预算当可用资源。

**缺失替代**：候选标“可行性未核定”，保留原方案；可列待核定约束，不运行带虚构成本/容量的真实方案排序。

### G7｜数据许可与赛方说明

**字段（3 包）**

- D19 权利与来源：提供方/权利主体、原始出处、获取日期/版本、许可文本、参赛用途与自采登记结论、有效期限及撤回联系人角色。
- D20 使用边界：本地处理、团队访问、第三方模型/云处理、聚合图表、原文片段、视频/答辩、脚本附件与再分发分别允许什么；保留期限与删除要求。
- D21 口径附件：正式字段字典、稳定匿名平台跨年映射与采集范围、官方评测集入口及使用规则、培养/招生样例、缺失材料的正式答复。

**用途**：决定材料可否入分析、可否公开复现，确认匿名平台与赛方要求；许可不替代数据质量验收。

**最小可用样本**：每个来源与版本各一份覆盖实际使用范围的授权/公开许可及字段说明；
每个缺失附件各一条“提供/不提供/受限”的赛方书面答复。未答复不视为默认授权。

**责任角色**：校方数据管理/授权部门与赛方指定联系人确认；团队数据负责人建台账、协调者审批公开清单。

**验收标准**：来源、版本、允许操作、公开范围和期限明确；各附件有责任方，
“脱敏”不等于允许再分发，稳定匿名映射不要求公开真实平台身份；口头答复须形成可留存确认。

**缺失替代**：不公开许可不明材料与图表，不传第三方模型；演示用明确标识的合成示例，
公开支撑仅含获授权输入及复现步骤。许可或评测集缺失照实记录，不能声称官方评测通过。

## 三、隐私、授权与验收回执

1. **最小化申请**：不申请姓名、学号、身份证、联系方式、详细住址、简历、个人级成绩/就业轨迹。
   若学校内部需要关联，由学校在本域完成，仅交经批准的专业/届别等汇总；团队不持有映射钥匙。
   散列学号仍可能关联个人，不能当匿名数据替代品；自由文本先由提供方清除可识别信息。
2. **防止反推**：校方制定小组最小公开人数、合并维度和互补抑制规则；检查总计与分组能否反推。
   阈值未定或小组过细则不接收/不展示相应细分，不能宣称某个固定阈值保证匿名。
3. **分别授权**：参加调查、内部研究、比赛展示、公开代码附件、第三方处理分别确认；
   不因一项获批就扩用。团队按角色访问，经批准的存储渠道与到期清理留回执；没有授权不向外传。
4. **回执流程**：供给负责人为 D01–D21 各登记“未申请/已申请/受限/已收待验/验收通过/退回”，
   写文件位置、版本、缺项、用途限制、责任角色、约定交付日期和复核者。
   本文初始均为“待申请”，验收通过后再由协调者更新报告与检查表。
5. **解除缺口的顺序**：先定学校/专业/届别并收 D01–D02、D04–D09 和许可；
   再以 D10–D12、D16–D18 核定动作、方向和资源；D03、D13–D15 满足比较条件后才评真实结果。
   任何一组缺失都在对应判断处停下，不把数据申请计划当完成证据。
